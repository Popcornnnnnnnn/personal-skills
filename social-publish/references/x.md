# X

X rewards compression and a strong first line. The package should feel like a useful observation from the maker, not a miniature press release.

## Default format

- Prepare one standard post first. Keep it within the current standard-account limit; do not assume Premium or long-post access.
- Count the finished text conservatively, including the visible URL. Recheck the live composer when publishing.
- Use a thread only when the product needs explanation that cannot be removed without losing value. Keep it to roughly 2-4 posts, with one idea per post.
- Put the canonical link in the final post of a thread unless the opening post needs it for context.

## Writing style

- Open with a recognizable problem, result, or technical observation.
- Name what was built and why it is different in plain language.
- Prefer one link and zero hashtags. Use at most one directly relevant hashtag when it materially aids discovery.
- Avoid generic launch phrases, stacked feature lists, repeated calls to action, and engagement bait.
- Do not publish duplicate or near-duplicate posts, repeatedly delete and repost, or reuse the same link with no new commentary.

## Images

- Default to one strong landscape visual with a readable real UI. A 16:9 export such as 1600x900 or 1200x675 is a practical starting point; inspect the live crop before publishing.
- X currently supports multiple media items, but one image is usually clearer for a compact product post. Use additional images only when each one carries distinct information.
- Keep key UI and text away from edges and provide useful alt text in the manual checklist.

## Package

Use `x/` with:

- `POST.md`: exact single-post copy, link, character count, image, and alt text.
- `THREAD.md`: optional; number every post and provide per-post character counts.
- `CHECKLIST.md`: composer limit check, link preview, crop, alt text, and duplicate-content check.
- `assets/`: self-contained X-ready media.
