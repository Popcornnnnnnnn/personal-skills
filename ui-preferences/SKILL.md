# Personal UI preferences

以下是作者的个人默认偏好，供选择采用，不作为所有产品的通用要求。应用于本次任务涉及的界面。用户本次明确要求优先于以下默认偏好。所需偏好全部在本文件中，无需检索旧经验库；参考入口按任务需要使用。

开放式、强调视觉质量的 Web 任务：先自行查看相关的完整页面、模板、主题和组件预览，确定整体构图、视觉焦点、排版、色彩与材质，再选择具体组件。一个候选不合适时继续探索其他材料或自行设计，不要在拒绝一个动效后结束视觉探索。浏览器预览按 `agent-browser` 默认使用 Neo，用户明确指定其他浏览器时遵从当次选择；按实际画面修改。普通功能修复无需走这套流程。

**先用界面表达功能，再决定哪些文字必须存在。** 这适用于整个应用的导航、页面、卡片、设置和空状态。优先通过布局、控件、明确的图标和交互反馈表达功能；不要给每块区域配一句介绍。删除口号、拟人化寒暄、重复标题、显而易见的操作说明和无须处理的状态宣告，例如“需要时，帮你想一句”“已就绪，随时可用”。不能帮助用户识别功能、完成操作或作出判断的文字，默认删除，不换成另一句文案。必要的功能名和简短标签保留；无歧义的常见操作可用图标按钮，并提供 tooltip 和无障碍名称，不把所有文字机械替换成难懂的图标。帮助按需展开；涉及权限、数据发送、费用或不可逆操作的必要说明，在相关操作处清楚呈现，不在常驻页面反复铺陈。

**简洁靠减少负担，不靠放大控件或掏空页面。** 日常工具默认采用紧凑、可操作的布局；不使用宣传式大标题、巨型状态卡片或无意义留白填充窗口。快捷键用紧凑的原生符号组合（如 `⌃⌥R`）或标准快捷键录入控件，融入相关操作行；不做成带厚阴影的巨大立体键帽，不用分隔加号把组合撑成展示区。交付前逐页检查多余文案、重复入口和装饰性控件，而不只检查首页。

1. **所有可点击控件必须有 hover 反馈。** 按钮、图标按钮、链接、筛选标签、分段控件、可点击行和卡片，鼠标移入时都必须有清晰可见的变化，仅改变鼠标指针不够。覆盖默认及已选中但仍可点击的状态。Hover 与选中、按下状态应可区分，不引发布局移动；禁用控件不呈现可操作反馈。交付前逐项实际移入鼠标检查；未完成实际验证时明确标注未验证，不把写了样式当作效果已验证。

2. **默认使用一致、可见的圆角。** 主要面板、卡片、输入框和实体按钮应有适度圆角，不要只给 Logo 做圆角，也不要无故改成全直角界面。可点击列表行和纯文字按钮可保持直边；在实际画面中检查整体是否统一。

3. **默认英文，支持中英文切换。** 应用自有界面、菜单、提示及内置文案提供完整的英文和中文版本，默认显示英文；提供语言切换入口并保存用户选择。用户输入和来源内容保留原语言，不自动翻译。

4. **默认浅色，支持浅色、深色和跟随系统。** 未设置时使用浅色；提供切换入口，有持久设置时保存并尊重用户已选外观。两种外观下的文字、控件和交互状态都应清晰可辨。

5. **相关元素共享布局秩序。** 重复区域的列边界、标签、控件和同级卡片应对齐，避免无意义的空白；明确的主次关系允许不对称，窄窗口允许改为单列。

6. **长标题按需展开。** 紧凑桌面列表中，仅对实际截断的标题，在鼠标停留于标题文字上 1 秒后显示全文；短标题不触发，不移动或遮挡邻近内容，并保留键盘读取全文的方式。需要直接阅读的重要标题优先完整展示。

7. **可选设置允许清空。** 清空已有可选值后应能保存，并真正撤销旧值；必填项仍需校验。已有版本历史时，清空也应可恢复。

8. **紧凑 macOS 面板使用轻量滚动指示。** 优先在滚动时显示、不占布局空间的指示条。需要拖动精确定位、持续显示位置或满足平台辅助功能要求时，保留合适的原生滚动条。

9. **Logo 在实际使用位置保持清晰。** 优先使用透明独立标志，保证深浅背景下的对比度；透明轮廓应存在于素材本身，不依赖 CSS 裁切。品牌或平台要求底板时保留底板，并检查小尺寸实际效果。

10. **[TokenTracker](https://www.tokentracker.cc/)：视觉参考。** 适合开发者工具的紧凑导航、清晰层级、深色层次和克制的数据强调；按任务借鉴，不默认套用整套风格。

11. **[React Bits](https://reactbits.dev/)：组件资源。** 按具体元素或交互选择组件，检查预览、依赖和配置，适配现有产品；不把文档网站当设计模板，不为装饰而引入效果。

12. **[SwiftUI macOS App Template](https://github.com/SohrabZ/swiftui-macos-app)：原生实现参考。** 按需借鉴窗口、主题、设置和应用生命周期等部分，匹配项目架构与系统版本；替换演示内容，避免整套照搬。

13. **[theSVG](https://thesvg.org/)：品牌 Logo 资源。** 需要展示现有品牌或产品 Logo 时，优先在此查找并选用合适的 SVG 素材，检查实际尺寸及深浅背景下的清晰度。

14. **[21st](https://21st.dev/)：视觉方案与组件资源。** 从相关的 React 组件、完整模板和主题中寻找适合产品的画面方向；查看实际预览，再检查拟采用材料的代码、依赖和使用条件，按现有技术栈改造。
