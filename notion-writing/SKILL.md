# Notion writing methods

These are personal working preferences, not universal Notion requirements. A specific user request and an established project/team schema take priority. Publishing or installing this skill grants no permission to save a conversation, execute a task, send a message, schedule work, delete pages or change access.

## Before a write

Read the complete configured owner profile when present. It contains the actual workspace, destinations, per-channel language rules and existing local constraints. Keep those bindings out of public output. If there is no profile, resolve an authorized workspace and destination from the current task before writing. A browser workspace switch does not change a connector's identity.

Fetch the actual parent, schema and existing record. Search by meaning plus stable source, canonical URL, date or recording identity. Reuse the correct record; avoid parallel inboxes, category copies and workspace-root drafts. An inaccessible target is a reported blocker, not a reason to select another account or sandbox.

## Writing preferences

- Put the reader's purpose, conclusion and necessary background first. Preserve evidence, meaningful examples, source links and material uncertainty.
- Prefer concise English navigation, titles and generated document prose, except where the user or an established channel has another explicit language rule. Preserve human text and source originals.
- Use prose, lists, tables and diagrams when they help the reader. Keep nonessential timestamps, local paths, internal IDs, execution receipts and model-processing details in separate operational records. Include original material when requested.
- One source usually becomes one complete article. Keep its original source accessible. Saving is not proof the human has read, liked or accepted it.
- Use stable icons to identify page purpose, without decorating every heading. Keep directory pages brief and avoid empty structure.
- For substantial editable prose, apply an installed humanizer when available while preserving factual qualifications and the writer's voice.

## Filing and views

File by purpose in an existing suitable location. A project's established destination takes priority over a personal inbox. Reading, journals, recordings, tasks and business documents can have distinct destinations; do not merge them just to simplify navigation.

For reading libraries, the author's default is a native List with Side peek, a complete article behind each title and only useful human properties visible. Hide processing metadata and Summary where the selected database's rules call for it. Preserve fields and values when changing presentation. Operational trackers retain their established layouts.

Preserve date meanings and user-selected sort/filter/view state. Do not invent a deadline, reminder, completion or owner. Task progress, evidence, severity, reading disposition and human judgment are separate concepts. A positive practice label requires a specific human nomination where the learning workflow uses that distinction.

## Safe updates and acceptance

Use the smallest targeted update. Preserve comments, children, attachments, links, human edits and schema unless the task authorizes changes. Move existing IDs rather than recreate pages during an authorized reorganization. Keep unique material when resolving duplicates; a redirect can preserve links, and deletion remains a separate authorization.

After writing, fetch the affected record and check its actual parent, identity, body, children/media and human fields. Verify the rendered UI when acceptance depends on layout or reminder behavior. Reconcile unknown outcomes before retrying and stop once acceptance passes. Installing this skill or configuring a writer does not prove an already-running agent has loaded it.

## Maintain the method

Keep reusable methods here. Update private destinations, ongoing grants and account configuration in the local owner profile, after the corresponding user instruction. Preserve current constraints when separating these layers; do not convert historical receipts into new authority or claim other writers were synchronized without evidence.
