# Acceptance and bounded repair

Compare the intended run/account/folder scope with observed records and final outputs. Count accessible, read, archived, removed, invalid and retained items separately. Keep raw receipts out of reader-facing prose.

A run can finish with unresolved items. A saved article does not prove full source coverage, a source-cleanup click does not prove the final state, and a local receipt is not independent remote verification. Read back exactly what the completion claim requires.

For auditable processing, use the existing `state.py audit --run ID --file receipt.json` append-only audit entry. Keep `status` and an existing `report_path`; include `execution_audit` version 1 with the original `run_id`, `date`, `counts`, and `stages`. Counts `discovered`, `fully_read`, `saved_verified`, `unfavorited`, and `remaining` are nonnegative integers, or null when unknown. Keep daily-report delivery and message delivery as separate stages; a saved article proves neither.

Each stage identifies `id`, `platform` (or null), optional exact `source_key`, `status` (`success`, `failed`, `unknown`, or `not_attempted`), explicit `started_at`/`ended_at` (timezone-aware timestamps or null), actual `error`, boolean `cause_proven`, `next_step`, and `evidence` entries containing existing file `path` and SHA-256 `sha256`. Put observed source/output IDs and URLs in `result`. Record stage boundaries when they occur, including before a mutation; retain original intent/reconciliation guards. If earlier boundaries were not captured, leave them null rather than treating a file timestamp, current connectivity, schedule, or report claim as execution evidence. The helper checks referenced bytes and appends a snapshot; it does not independently prove platform truth. Preserve the referenced receipts. Later corrections append a new audit entry without changing old entries.

Repair only an authorized, understood failure. Preserve original evidence and human decisions; do not restart an entire successful batch, change schedules, install dependencies or alter accounts to make a dashboard green. If no actionable step remains, state the specific remaining limit and recovery condition.
