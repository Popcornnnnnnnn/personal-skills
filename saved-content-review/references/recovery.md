# Recovery and owner-operated schedules

This package does not schedule work. Read the user's actual configured schedule, allowed accounts/folders, output destinations and authorization before resuming an existing operation. The owner's original running-collector contract can live in the private profile.

Preserve completed checkpoints and source evidence. Resume only the failed or incomplete step when it is still in scope. A blocker in one platform does not stop independent authorized work on another platform. Do not create duplicate API jobs or repeat uncertain external mutations.

A failed refresh is failed coverage, not an empty collection. Distinguish missing local data, unavailable remote content, authentication, OS permissions and unsupported tools. Never repair a blocker by extracting credentials or widening access.

Local `state.py` maintains atomic evidence checkpoints. `night_watch.py` is a macOS-specific status/power helper for an already configured owner workflow; no command is authorized merely by being present. Keep schedule/power configuration private and do not start, extend or restore background work without that task's authorization.
